PUBLIC DEVELOPMENT ORDER

LatticeVeil Roadmap

This page shows the current development order in public-facing form. It is arranged so the next concrete work is clearer, the later systems are separated, and the platform plans stay in their own lane.

Current Focus

Launcher auto-update is still the main priority. The updater feature is already added in code, but it still needs real end-to-end testing before it can be treated as fully proven. Before the first health-and-hunger release, the next concrete game work is a stabilization pass for tree generation, terrain and ocean generation, and profile or friends performance.

Status: the updater is ADDED, NEEDS TESTING. The first real gameplay build used to validate it is still the health, hunger, and fall-damage update, but that build now comes after the current stabilization pass.

Before Public Release

A usable GitHub version comes after the updater has been validated on a real gameplay build, the current tree and terrain problems are corrected, health and hunger are working, the world data contract is cleaner, direct launch is in place, and the game has a more dependable playable core.

Public-build gate: updater validated on a real feature release, worldgen and profile stabilization complete, health and hunger shipped, world data cleaned up, and the core survival/world path stable enough to represent the project properly.

Concrete Build Order Details

Added, Needs Testing

Launcher Updater

  • Add live version checking for game and launcher builds.
  • Show the current version clearly in the launcher UI.
  • Add an `UPDATE AVAILABLE` state and update button.
  • Download update packages with visible progress.
  • Reuse staged install and replace behavior similar to the current asset updater.
  • Preserve settings, auth data, logs, and installed assets during update.
  • Update launcher-driven version metadata after success.
  • Add rollback or safe failure behavior.
  • Remember the last checked version to avoid repeated prompts.
  • Add graceful offline fallback when update services are unavailable.
  • Test dev-to-release and release-to-release update paths.
Needs Added

Tree Generation Reliability + Final Canopy Pass

  • Replace the single hardcoded simple-tree path with deterministic world-space tree descriptors.
  • Stop letting chunk-edge rejection decide whether a tree exists.
  • Keep the standard trunk height at 4 blocks.
  • Rebuild the canopy into the compact layered target shape instead of a flat slab.
  • Add at least two deterministic variants in the same canopy family.
  • Add taller trunk-only forest variants in the 6 to 8 block range.
  • Keep grasslands and hills on the shorter standard tree family.
Needs Added

Terrain Relief + Ocean Biome Fix

  • Separate broad landmass shape from inland relief and smaller warped detail.
  • Use a low-frequency landmass mask for land, coast, and ocean placement.
  • Add broader inland relief for rolling uplands, valleys, and ridge-like variation.
  • Add smaller warped detail so terrain stops reading as evenly repetitive.
  • Align ocean biome classification and terrain thresholds.
  • Add cleaner coast, shallow ocean, and deeper basin behavior.
  • Keep seabeds reliably below sea level.
  • Make beaches and shorelines transition more cleanly.
Needs Added

Profile/Friends Performance + UI Cleanup

  • Show cached profile text immediately on open.
  • Refresh remote avatar and banner in the background after text is already visible.
  • Add a lightweight local cache for the last successful Veilnet profile payload.
  • Remove MY ID: from STATUS.
  • Remove CONFIG: from STATUS.
  • Keep the status panel focused on EOS/online state and refresh result.
  • Rework friends, requests, and blocked users into a cleaner list with icon + primary/secondary text.
Needs Added

Health Then Hunger Validation Slice

  • Add a visible health bar.
  • Add damage and healing hooks needed for health to matter.
  • Add a visible hunger bar.
  • Add hunger drain rules.
  • Add basic starvation behavior.
  • Add fall damage as part of the first health-system pass.
  • Use a simple first-pass fall rule: falls of 3 blocks or less are safe, and 4+ block falls deal 1 heart of damage per block beyond 3.
  • Add save/load support for survival values.
  • Make the survival UI readable and stable.
  • Ship this as the first real gameplay update through the updater.
Needs Added

`world.lvc` Cleanup

  • Remove duplicate or unused entries.
  • Keep canonical core fields: `Name`, `GameMode`, `CreatedAt`, `EnableCheats`, and `WorldVersion`.
  • Move gameplay settings to `Gameplay.*` only.
  • Move player settings to `Player.*` only.
  • Move world size to `WorldGeneration.WorldSize.*` only.
  • Reject partial legacy mixes instead of carrying both forever.
Needs Added

Launcher And Workflow Improvements

  • Direct launch via `CTRL` and `-game`.
  • Silent background auth and hash checks with fast offline fallback.
  • Debug mode activation, debug overlay, dump tools, UI inspection, and timing/report export.
  • Launcher news tab with feed filters, last-read tracking, cache, and offline fallback.
