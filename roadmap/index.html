PUBLIC DEVELOPMENT ORDER

LatticeVeil Roadmap

This page shows the current development order in public-facing form. It is arranged so the next concrete work is clearer, the later systems are separated, and the platform plans stay in their own lane.

Current Focus

Launcher auto-update is still the main priority. The updater feature is already added in code, but it still needs real end-to-end testing before it can be treated as fully proven.

Status: the updater is ADDED, NEEDS TESTING. The next real gameplay build used to validate it is the health-and-hunger update.

Status Legend

Already built, still not validated properly

Use this for systems that already exist in code but still need real runtime or live-path testing.

Needs Added

Concrete next implementation work

Use this for named systems that are clearly next but are not actually built yet.

Planned

Confirmed later system

Use this for confirmed future work and idea pools that are decided on but are not immediate.

Unlikely

Use this for work that is currently unrealistic, mostly for financial reasons.

Before Public Release

A usable GitHub version comes after the updater has been validated on a real gameplay build, health and hunger are working, the world data contract is cleaner, direct launch is in place, and the game has a more dependable playable core.

Public-build gate: updater validated on a real feature release, health and hunger shipped, world data cleaned up, and the core survival/world path stable enough to represent the project properly.

Concrete Build Order Details

Added, Needs Testing

Launcher Updater

  • Add live version checking for game and launcher builds.
  • Show the current version clearly in the launcher UI.
  • Add an `UPDATE AVAILABLE` state and update button.
  • Download update packages with visible progress.
  • Reuse staged install and replace behavior similar to the current asset updater.
  • Preserve settings, auth data, logs, and installed assets during update.
  • Update launcher-driven version metadata after success.
  • Add rollback or safe failure behavior.
  • Remember the last checked version to avoid repeated prompts.
  • Add graceful offline fallback when update services are unavailable.
  • Test dev-to-release and release-to-release update paths.
Needs Added

Health Then Hunger Validation Slice

  • Add a visible health bar.
  • Add fall damage as part of the first health-system pass.
  • Use a simple first-pass fall rule: falls of 3 blocks or less are safe, and 4+ block falls deal 1 heart of damage per block beyond 3.
  • Add damage and healing hooks needed for health to matter.
  • Add a visible hunger bar.
  • Add hunger drain rules.
  • Add basic starvation behavior.
  • Add save/load support for survival values.
  • Make the survival UI readable and stable.
  • Ship this as the first real gameplay update through the updater.
Needs Added

`world.lvc` Cleanup

  • Remove duplicate or unused entries.
  • Keep canonical core fields: `Name`, `GameMode`, `CreatedAt`, `EnableCheats`, and `WorldVersion`.
  • Move gameplay settings to `Gameplay.*` only.
  • Move player settings to `Player.*` only.
  • Move world size to `WorldGeneration.WorldSize.*` only.
  • Reject partial legacy mixes instead of carrying both forever.
Needs Added

Launcher And Workflow Improvements

  • Direct launch via `CTRL` and `-game`.
  • Silent background auth and hash checks with fast offline fallback.
  • Debug mode activation, debug overlay, dump tools, UI inspection, and timing/report export.
  • Launcher news tab with feed filters, last-read tracking, cache, and offline fallback.
