PUBLIC DEVELOPMENT ORDER

LatticeVeil Roadmap

This roadmap reflects the current V15.0.0 state. It separates what is already shipped, what is being cleaned up next, and what is planned for later so the public build order is easier to follow.

Current Public State

V15.0.0 "Soulbound Signals" is the current game release. The project now has real launcher updating, asset updating, world creation, terrain generation, multiplayer hosting and joining, friends/profile surfaces, survival HUD foundations, commands, PvP controls, death/respawn work, souls, installer delivery, and a refreshed uninstaller path.

The next major work is not another distribution reset. The next pass is focused on player appearance, skin upload/storage, world import quality-of-life, social/profile cleanup, and better host/admin tools.

Finished / In Current Builds

Shipped

Launcher, installer, and update delivery

  • Installer-first public download flow.
  • Launcher checks the latest public game release and handles game updates.
  • Asset release checking, download, extraction, and installed markers are in place.
  • Official online gating and build verification exist for public online play.
  • Build GUI exists for local dev/release packaging and asset zip creation.
  • The installer now embeds the updated uninstaller.
Shipped

World creation and world data

  • Create-world flow exists.
  • Terrain and flatlands world types exist.
  • World generation toggles for structures, caves, ores, and trees exist.
  • World preview generation exists.
  • world.lvc is the active world metadata format.
  • The uninstaller now reads the current sectioned world.lvc format for mode, seed, cheats, and world type.
  • Installer world import now handles duplicate worlds with safer options and copy names such as World Name (1).
Shipped

Terrain, sandbox, and inventory foundations

  • Terrain generation, biome services, ocean/forest/hills/desert/grasslands support, chunk storage, mesh, and region foundations exist.
  • Movement, flying, noclip, block break/place, raycast, hotbar, and held-block rendering exist.
  • Inventory storage and UI exist.
  • Artificer catalog, search, favorites, persistence, and live inventory viewing plumbing exist.
  • Chat and command foundations exist.
Shipped

Survival and souls

  • Visible health foundation exists.
  • Visible hunger foundation exists, with commands and UI groundwork ready for fuller behavior.
  • Fall damage exists and needs continued tuning.
  • Death/respawn handling has been improved across normal play and pause-menu edge cases.
  • Recoverable souls exist.
  • Soul claiming is tied to crouch behavior instead of generic held Shift state.
  • Souls show the fallen player's name above them.
Shipped

Multiplayer and social UI

  • LAN and online multiplayer foundations exist.
  • Host/join/browser screens exist.
  • Friends, requests, blocked users, invites, and presence surfaces exist.
  • Multiplayer browser now better distinguishes request-join, invited, whitelisted, and joinable states.
  • Invite sending uses host presence/world/mode data instead of assuming invite-table mode fields.
  • Invite popup/list presentation was cleaned up with better world, mode, status, and duplicate-invite feedback.
  • Join messages were improved so existing players receive clearer join feedback.
  • Host disconnects now send HOST LEFT THE GAME through LAN/EOS shutdown reasons and the multiplayer disconnect screen.
  • TAB list now uses profile images and larger player presentation with banner-backed rows.
  • Profile and friends status text now better reflects launcher/game state.
Shipped

Commands and moderation basics

  • Working /kill command exists for self, one player, or multiple named players.
  • /kill player-name autofill was added.
  • PvP behavior and related command handling were improved.
  • Give-item feedback now tells the giver they gave the item instead of repeating the recipient message.
  • Chat slash-open behavior no longer conflicts with inventory opening.
  • Kick messaging was improved so players see the intended kick message before being returned.

Next Update Targets

Next Up

Launcher player model and skin system

  • Add a live 3D player model preview to the launcher/profile area.
  • Let players see the selected skin before launching.
  • Add working skin selection with local cache and a safe default appearance.
  • Support raised cosmetic overlay layers as shallow 3D surfaces over the base player model.
  • Keep the skin format and presentation branded as LatticeVeil's own system.
Next Up

Veilnet skin uploads and R2 migration

  • Use Cloudflare R2 for profile images, banners, and skin textures.
  • Use Supabase as the source of truth for ownership, active asset IDs, object keys/URLs, hashes, and timestamps.
  • Allow skin uploads and skin switching from the Veilnet website.
  • Migrate existing Supabase-hosted profile pictures and banners to R2 during the skin-system pass.
  • Update the website, launcher, and game to fetch profile images, banners, and skins from the new R2-backed locations.
  • Use hash/version checks so cached images and skins are invalidated reliably.
Next Up

.lvworld import quality-of-life

  • The game should auto-detect .lvworld files placed in Documents\LatticeVeil\Worlds on launch.
  • Detected .lvworld files should import into proper world folders and then be moved or marked so they do not re-import every launch.
  • Duplicate imports should use World Name (1), World Name (2), and so on.
  • The imported world.lvc display name should be updated so the in-game list matches the folder name.
  • Add an IMPORT WORLD button to the world/select screen.
  • Create a proper texture/icon for the import button.
  • Manual imports and launch-time imports should share validation, duplicate naming, and player-facing error handling.
Needs Follow-Up

Multiplayer reliability and host lifecycle

  • Keep multiplayer browser refresh reliable so hosted worlds do not disappear while active.
  • Keep testing host-disconnect handling across LAN/EOS edge cases now that HOST LEFT THE GAME is wired through the disconnect path.
  • Continue polishing disconnect behavior across kick, host shutdown, connection loss, and return-to-multiplayer routing.
  • Keep join messages consistent for invited, whitelisted, and normal joined players.
  • Continue improving invite popup presentation and contained scrolling world-name text.
Needs Follow-Up

Profile/friends cleanup

  • Reduce social refresh cost.
  • Keep saved friends updating even when the game window is not focused.
  • Make online/offline/launcher/in-game status text consistent across profile, friends, and invite screens.
  • Keep avatar/banner fetching reliable without adding avoidable lag.
  • Keep blocked-user rows cheap by skipping unnecessary presence/image fetches.

Planned Later Systems

Planned

  • Temperature and environmental pressure later.

Planned

World and dimension expansion

  • Skyblock option and rare sky islands.

  • See-through portals, temporary rifts, ancient gateways, and portal instability stages.
Planned

Automation and circuits

  • Hidden wiring, digital/analog signals, pulse/static timer blocks, and chained timing logic.
Planned

Progression, resonance, and lore systems

  • Finished Attunement progression beyond the current placeholder.
  • Instability progression and balanced-state risks/rewards.

  • Echo-linked encounters and environmental storytelling.
  • Ancient technology blocks, lore tablets, and Continuist-linked structures.

Planned
