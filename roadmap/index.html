PUBLIC DEVELOPMENT ORDER

LatticeVeil Roadmap

V16.1.0 "Veilnet Skinlink" is the current public release. V17.0.0 "Veilwalker Survival" is in Windows development. This roadmap separates shipped work, the active survival release path, and later systems so the public build order is easy to follow.

Current Public State

V16.1.0 "Veilnet Skinlink" is the current public game release. The project now has launcher and asset updating, world creation, terrain generation, multiplayer hosting and joining, friends/profile surfaces, survival HUD foundations, commands, PvP controls, death/respawn work, SOUL recovery, website-edited account skins, launcher skin sync, tray controls, installer delivery, and a refreshed uninstaller path.

The active Windows development target is V17.0.0 "Veilwalker Survival": validate and complete a basic playable survival loop before moving into broader import, social, admin, and dedicated-host work.

Finished / In Current Builds

Shipped

Launcher, installer, and update delivery

  • Installer-first public download flow.
  • Launcher checks the latest public game release and handles game updates.
  • Asset release checking, download, extraction, and installed markers are in place.
  • Official online gating and build verification exist for public online play.
  • Build GUI exists for local dev/release packaging and asset zip creation.
  • The installer now embeds the updated uninstaller.
Shipped

World creation and world data

  • Create-world flow exists.
  • Terrain and flatlands world types exist.
  • World generation toggles for structures, caves, ores, and trees exist.
  • World preview generation exists.
  • world.lvc is the active world metadata format.
  • The uninstaller now reads the current sectioned world.lvc format for mode, seed, cheats, and world type.
  • Installer world import now handles duplicate worlds with safer options and copy names such as World Name (1).
Shipped

Terrain, sandbox, and inventory foundations

  • Terrain generation, biome services, ocean/forest/hills/desert/grasslands support, chunk storage, mesh, and region foundations exist.
  • Movement, flying, noclip, block break/place, raycast, hotbar, and held-block rendering exist.
  • Inventory storage and UI exist.
  • Artificer catalog, search, favorites, persistence, and live inventory viewing plumbing exist.
  • Chat and command foundations exist.
Shipped

Player model, website skins, and launcher sync

  • In-game player model rendering exists for local and remote players.
  • The game loads the default player skin texture from the asset pack.
  • Player skin textures hot-reload locally when the skin file changes.
  • A generated fallback skin exists when the asset skin cannot be loaded.
  • The Veilnet website can edit and save the same active account skin used by the launcher and multiplayer.
  • The website preview uses a game-style layered player model with transparent overlay support.
  • Browser local backups show visual cards and block exact visual duplicate entries.
  • The launcher can import browser-backed skins into the local skin folder and refresh an already-open skin GUI.
  • The launcher Skins button reloads the current cloud/local skin state instead of only checking at startup.
Shipped

Launcher tray and Veilnet login handoff

  • Minimize and close-to-tray behavior exists with separate saved preferences.
  • The tray menu can open the launcher, launch or kill LatticeVeil, open the skin GUI, open the signed-in profile, login/logout, or exit.
  • The tray menu follows the launcher dark/light theme and keeps the profile controls at the top.
  • Opening the launcher again restores the existing launcher window instead of showing an already-open warning.
  • Veilnet login returns to the launcher without a manual generate-code button and can offer OK or Launch after login succeeds.
Shipped

Survival and souls

  • Visible health foundation exists.
  • Visible hunger exists with difficulty-based hunger drain.
  • Natural regeneration and starvation pressure are wired through difficulty tuning.
  • Health and hunger are saved in player world state and sync through multiplayer player state.
  • Health, hunger, and attunement can be adjusted with the /set command.
  • Fall damage exists and still needs continued tuning.
  • Death/respawn handling has been improved across normal play and pause-menu edge cases.
  • Recoverable souls exist.
  • Soul claiming is tied to crouch behavior instead of generic held Shift state.
  • Souls show the fallen player's name above them.
Shipped

Multiplayer and social UI

  • LAN and online multiplayer foundations exist.
  • Host/join/browser screens exist.
  • Friends, requests, blocked users, invites, and presence surfaces exist.
  • Multiplayer browser now better distinguishes request-join, invited, whitelisted, and joinable states.
  • Invite sending uses host presence/world/mode data instead of assuming invite-table mode fields.
  • Invite popup/list presentation was cleaned up with better world, mode, status, and duplicate-invite feedback.
  • Invite popups and friend profile previews use contained scrolling world-name text.
  • The multiplayer browser world-name column scrolls contained long names instead of clipping them.
  • Join messages were improved so existing players receive clearer join feedback.
  • Host disconnects now send HOST LEFT THE GAME through LAN/EOS shutdown reasons and the multiplayer disconnect screen.
  • TAB list now uses profile images and larger player presentation with banner-backed rows.
  • Profile and friends status text now better reflects launcher/game state, including saved-friend presence refresh.
Shipped

Commands and moderation basics

  • Working /kill command exists for self, one player, or multiple named players.
  • /kill player-name autofill was added.
  • PvP behavior and related command handling were improved.
  • Give-item feedback now tells the giver they gave the item instead of repeating the recipient message.
  • Chat slash-open behavior no longer conflicts with inventory opening.
  • Kick messaging was improved so players see the intended kick message before being returned.
  • Host-only /op and /deop command basics exist for operator permissions.

After V17 Survival

Next Up

.lvworld import quality-of-life

  • The game should auto-detect .lvworld files placed in Documents\LatticeVeil\Worlds on launch.
  • Detected .lvworld files should import into proper world folders and then be moved or marked so they do not re-import every launch.
  • Duplicate imports should use World Name (1), World Name (2), and so on.
  • The imported world.lvc display name should be updated so the in-game list matches the folder name.
  • Add an IMPORT WORLD button to the world/select screen.
  • Create a proper texture/icon for the import button.
  • Manual imports and launch-time imports should share validation, duplicate naming, and player-facing error handling.
Next Up

Multiplayer admin panel

  • Replace the current pause-menu INVITE FRIENDS entry with an ADMIN PANEL entry for hosts and authorized admins.
  • Keep friend invite/send-invite controls inside the admin panel.
  • Support appointing admins separately from ops.
  • Let hosts grant specific permissions instead of blanket power.
  • Permission categories should cover build zones, breaking blocks, placing blocks, invites, and future moderation tools.
  • TAB list role tags should show HOST, OP, and configured admin roles.
Needs Follow-Up

Multiplayer reliability and host lifecycle

  • Keep multiplayer browser refresh reliable so hosted worlds do not disappear while active.
  • Keep testing disconnect behavior across kick, host shutdown, connection loss, and return-to-multiplayer routing.
  • Keep validating join messages for invited, whitelisted, and normal joined players under real multiplayer sessions.
  • Continue hardening invite and browser refresh behavior when host presence changes quickly.
Needs Follow-Up

Profile/friends cleanup

  • Reduce social refresh cost.
  • Keep avatar/banner fetching reliable without adding avoidable lag.
  • Keep blocked-user and large-list rows cheap as social lists grow.
