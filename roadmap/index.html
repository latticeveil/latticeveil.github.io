PUBLIC DEVELOPMENT ORDER

LatticeVeil Roadmap

This page shows the current development order in public-facing form. It is arranged so the next concrete work is clearer, the later systems are separated, and the platform plans stay in their own lane.

Current Focus

The current real-game focus is still cleanup on systems that already exist in code: profile and friends performance or UI cleanup first, then inventory usability polish. The launcher or updater flow, LAN or EOS multiplayer foundations, world creation, hotbar, and base inventory already exist. Health, hunger, and fall damage are now in the game as a first pass, and Veilwalker also has a placeholder Attunement lane. The next work is tuning, validation, and deciding what the non-placeholder Attunement loop should actually do.

Repo-verified status: launcher or updater flow is ALREADY IN CODE, not missing. Profile or friends and inventory are ADDED, NEED FOLLOW-UP. Health, hunger, fall damage, and the placeholder Attunement lane are now ADDED, NEED FOLLOW-UP rather than still being purely missing.

Before Public Release

The next stronger public-facing survival build comes after the current cleanup lanes are in better shape, the new health and hunger pass is tuned, fall damage feels right, the placeholder Attunement lane is either better integrated or safely optional, and the world data contract is cleaner.

Public-build gate now: profile or friends and inventory cleanup in better shape, the first survival slice validated in real play, Attunement clarified beyond placeholder status, updater confidence maintained on feature releases, world data cleaned up, and the core gameplay path stable enough to represent the project properly.

Concrete Build Order Details

Added, Needs Follow-Up

Launcher And Runtime Foundations

  • Launcher online or offline flow already exists in code.
  • Official build verification and online gating already exist.
  • Asset install and game release update flow already exist.
  • LAN discovery and hosting foundations already exist.
  • EOS or online hosting foundations already exist.
  • What remains is follow-up validation, clearer player messaging, and continued updater confidence on real gameplay releases.
Added, Needs Follow-Up

Profile/Friends Performance + UI Cleanup

  • Show cached profile text immediately on open.
  • Refresh remote avatar and banner in the background after text is already visible.
  • Keep the status panel focused on EOS or online state and refresh result.
  • Rework friends, requests, and blocked users into a cleaner list with icon plus primary or secondary text.
  • Reduce list and refresh friction instead of treating the whole feature as missing.
Added, Needs Follow-Up

Inventory Follow-Up Lane

  • Hotbar is already done as a real foundation.
  • Inventory storage and UI are already in code.
  • Artificer catalog, search, favorites, and persistence already exist.
  • What remains is normal-play usability cleanup, clearer interaction flow, and better presentation.
Added, Needs Follow-Up

Basic Survival Slice

  • Visible health is now in the build.
  • Visible hunger is now in the build.
  • Fall damage now exists as part of the first health-system pass.
  • The survival UI is now present in normal play instead of staying fully theoretical.
  • The next work is tuning, drain or starvation depth, longer-session validation, and clearer damage or recovery balance.
  • Veilwalker also now has a placeholder Attunement lane, but it should not be treated as the finished progression system yet.
  • The placeholder Attunement bar can be disabled per world if it is bothersome while that system is still in flux.
  • The first survival-era update still needs real runtime proof and follow-up balance work.
Added, Needs Follow-Up

`world.lvc` Cleanup

  • Remove duplicate or unused entries.
  • Keep canonical core fields: `Name`, `GameMode`, `CreatedAt`, `EnableCheats`, and `WorldVersion`.
  • Move gameplay settings to `Gameplay.*` only.
  • Move player settings to `Player.*` only.
  • Move world size to `WorldGeneration.WorldSize.*` only.
  • Reject partial legacy mixes instead of carrying both forever.
Added, Needs Follow-Up

Launcher And Workflow Improvements

  • Direct launch via `CTRL` and `-game`.
  • Silent background auth and hash checks with fast offline fallback.
  • Debug mode activation, debug overlay, dump tools, UI inspection, and timing/report export.
  • Launcher news tab with feed filters, last-read tracking, cache, and offline fallback.
